## 4. Decisions and Assumptions
1. **Frontend Service Layer (`docs/system_design/frontend.md`)**:
   - Create centralized API client in `frontend/src/services/apiClient.js` with `VITE_API_URL` (defaulting to `http://localhost:5000/api`).
   - Create `frontend/src/services/courseService.js` for `fetchCourses()` and `fetchCourseBySlug(slug)`.
   - Create `frontend/src/services/lessonService.js` for `fetchLessonBySlug(slug)`.
   - Create `frontend/src/services/progressService.js` for `fetchProgress()` and `saveProgress()`.
   - Keep `MOCK_COURSES` in `mockData.js` as a fallback in case the backend server is offline or restarting, ensuring zero UI breakage.
2. **Progress Hook Integration (`useProgress`)**:
   - Create `frontend/src/hooks/useProgress.js` to replace `useMockProgress.js`.
   - Coordinates with Clerk's `useAuth()` to retrieve session JWT tokens.
   - Synchronizes lesson completion and resume timestamps with `GET /api/progress` and `POST /api/progress`.
   - Supports optimistic updates for snappy UI response while persisting to the backend.
3. **Video Player Progress Tracking**:
   - Enhance `VideoPlayer.jsx` to mount the YouTube Iframe Player with `onStateChange` and periodic time updates (`setInterval` while playing).
   - Report elapsed playback seconds via `onTimeUpdate(seconds)`.
   - Auto-resume video playback from `resumeTimestamp`.
   - Provide manual "Save Timestamp" and "Mark as Complete" controls on the lesson page.
4. **Backend Auth Verification (Task 4.1)**:
   - Verify Clerk JWTs with both `clerkClient.verifyToken` and `authenticateRequest`.
   - Return 401 Unauthorized for invalid or missing tokens.

## 6. Requirements & Scope
- **In Scope (Phase 4)**:
  - Express Clerk JWT verification middleware.
  - Real API calls for all catalog, course detail, and lesson pages.
  - Video resume position tracking and periodic timestamp persistence.
  - "Mark as Complete" action synced to backend database.
  - End-to-end verification: browse -> open lesson -> watch video -> progress saved -> resume.
- **Out of Scope for Phase 4**:
  - Production deployment configs for Vercel/Render (reserved for Phase 5).

---

## 7. Security Considerations
- JWT tokens transmitted exclusively via `Authorization: Bearer <token>` headers.
- No database credentials or Clerk secret keys exposed to client browser.
- Input validation on all progress saving endpoints.

---

## 8. Acceptance Criteria
1. Backend verifies Clerk JWT for all requests to `/api/progress` (returns 401 when unauthorized).
2. Frontend catalog page loads real courses from `GET /api/courses`.
3. Frontend course detail page loads real modules and lessons from `GET /api/courses/:slug`.
4. Frontend lesson page loads real lesson content, video ID, and notes from `GET /api/lessons/:slug`.
5. Progress is saved to the backend with timestamp and completion status via `POST /api/progress`.
6. Progress is fetched and displayed on Course Detail, Lesson, and My Learning pages.
7. Linting passes with 0 errors across frontend and backend.

## 10. Exact Manual Test Steps
1. Start backend: `npm run dev:backend`.
2. Start frontend: `npm run dev:frontend`.
3. Open `http://localhost:5173/` - verify courses are loaded from backend API.
4. Click on "Next.js App Router in Depth" - verify course details, modules, and lessons are fetched from API.
5. Click on a lesson - verify video player loads with YouTube video ID and notes from backend.
6. Toggle "Mark as Complete" - verify network tab shows `POST /api/progress` returning 200 OK.
7. Navigate to My Learning (`/my-learning`) - verify completed count and course progress reflect the updated state.
