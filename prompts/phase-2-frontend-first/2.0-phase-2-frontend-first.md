## 4. Decisions and Assumptions
1. **Design System & Typography (Tasks 2.1, 2.2)**:
   - Finalize `docs/system_design/DESIGN.md` documenting every color hex, font size, border radius, shadow, and component pattern from `design-system.png`.
   - Update `frontend/tailwind.config.js` with exact `primary` and `neutral` color palettes, custom shadows (`sm`, `md`, `lg`, `xl`), and border radiuses.
   - Load `Playfair Display` and `Inter` from Google Fonts in `frontend/index.html`.
2. **Routing & Icons**:
   - Install `react-router-dom` for declarative client-side routing:
     - `/` and `/courses`: Public Catalog Page
     - `/courses/:courseSlug`: Course Detail Page
     - `/courses/:courseSlug/lessons/:lessonSlug`: Lesson Page
     - `/my-learning`: My Learning Dashboard (Protected)
   - Install `lucide-react` for high quality icons matching the design specs.
3. **Authentication (Tasks 2.3, 2.4)**:
   - Install `@clerk/clerk-react`.
   - Wrap the application in `ClerkProvider` in `App.jsx` using `import.meta.env.VITE_CLERK_PUBLISHABLE_KEY`.
   - If publishable key is missing or placeholder in dev, provide a graceful Mock Auth Fallback toggle so the developer can preview both SignedIn and SignedOut states without blocker errors.
   - Use `<SignedIn>`, `<SignedOut>`, `<SignInButton>`, `<UserButton>`, and route protection for `/my-learning`.
4. **Mock Data Structure**:
   - Create `src/services/mockData.js` exporting realistic courses, modules, lessons (with YouTube IDs from `videos.json`), and progress states matching the Supabase ERD in `docs/system_design/database.md`.
5. **Component Hierarchy**:

   - `src/pages/CatalogPage.jsx`

## 7. Security Considerations
- Frontend uses Clerk publishable key only (`VITE_CLERK_PUBLISHABLE_KEY`).
- No secret keys in client bundles.
- YouTube embed iframe uses safe attributes (`allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture"`).
