# Implementation Prompt: Phase 3 - Backend & Database

## 1. Goal
Implement Phase 3 of the Vibelearn platform according to `docs/roadmap.md` (Tasks 3.1 through 3.7) and `AGENTS.md`. Configure Supabase/PostgreSQL connection with Drizzle ORM, define schemas for `users`, `courses`, `modules`, `lessons`, and `progress`, generate database migrations, implement seeding from `docs/seed.ndjson` and `docs/videos.json`, and expose layered REST endpoints (`Routes -> Controllers -> Services -> Repositories`) for courses, lessons, and progress tracking.

## 3. Code & Specs Inspected
- Inspected `docs/system_design/database.md` ERD and table specifications:
  - `users`: `id` (text PK, Clerk User ID), `email` (text), `created_at` (timestamp).
  - `courses`: `id` (uuid PK), `title` (text), `slug` (text unique), `summary` (text), `cover_image_url` (text), `created_at` (timestamp).
  - `modules`: `id` (uuid PK), `course_id` (uuid FK), `title` (text), `position` (integer).
  - `lessons`: `id` (uuid PK), `module_id` (uuid FK), `title` (text), `slug` (text), `youtube_video_id` (text), `notes` (text), `position` (integer).
  - `progress`: `id` (uuid PK), `user_id` (text FK), `lesson_id` (uuid FK), `is_completed` (boolean), `resume_timestamp` (integer), `updated_at` (timestamp).
- Inspected `docs/system_design/backend.md` layered architecture rules:
  - Strict separation: Routes -> Controllers -> Services -> Repositories.
  - Feature modularity: `course`, `lesson`, `progress`.
  - No database queries outside repositories.
  - Centralized error handling.
- Inspected `docs/seed.ndjson` and `docs/videos.json`:
  - `seed.ndjson` contains courses (`_type: "course"`), modules, and lessons (`_type: "lesson"`).
  - `videos.json` contains YouTube IDs and durations keyed by lesson slug/identifier.

## 4. Decisions and Assumptions
1. **Drizzle ORM & Database Driver (Tasks 3.1, 3.2)**:
   - Use `drizzle-orm` with `postgres` (Postgres.js) driver for modern, fast PostgreSQL connections with Supabase.
   - Install `drizzle-kit` as devDependency for schema migrations (`npm run db:generate`, `npm run db:push`).
   - Define schema in `backend/src/db/schema.js` with full column types, primary keys, foreign keys, timestamps, and relations.
   - Configure `backend/src/db/index.js` with connection pool and Drizzle client. If `DATABASE_URL` is not set or in offline dev, provide a seed-backed repository fallback so API endpoints can be tested and verified out-of-the-box.
2. **Migrations & Seeding (Tasks 3.3, 3.4)**:
   - Configure migration output directory in `backend/src/db/migrations` using `drizzle-kit generate`.
   - Implement `backend/src/db/seed.js` script to parse `docs/seed.ndjson` and `docs/videos.json`, extract courses, modules, lessons, and insert them into the database or memory cache.
   - Add scripts to `backend/package.json`:
     - `"db:generate": "drizzle-kit generate"`
     - `"db:push": "drizzle-kit push"`
     - `"db:seed": "node src/db/seed.js"`
3. **Layered Architecture Implementation (Tasks 3.5, 3.6)**:
   - **Repositories:**
     - `course.repository.js`: `findAll()`, `findBySlug(slug)`, `findById(id)`.
     - `lesson.repository.js`: `findBySlug(slug)`, `findByCourseSlug(courseSlug)`, `findById(id)`.
     - `progress.repository.js`: `findByUser(userId)`, `findByUserAndLesson(userId, lessonId)`, `upsert(userId, lessonId, data)`.
   - **Services:**
     - `course.service.js`: Formats course catalog, calculates modules count and total duration.
     - `lesson.service.js`: Resolves lesson details, adjacent lessons (next/prev), and notes.
     - `progress.service.js`: Validates progress inputs, calculates completion metrics, saves timestamps.
   - **Controllers:**
     - `course.controller.js`: Handles `GET /api/courses` and `GET /api/courses/:slug`.
     - `lesson.controller.js`: Handles `GET /api/lessons/:slug`.
     - `progress.controller.js`: Handles `GET /api/progress` and `POST /api/progress`.
   - **Routes:**
     - `course.routes.js`: Registers public course endpoints.
     - `lesson.routes.js`: Registers public lesson endpoints.
     - `progress.routes.js`: Registers protected progress endpoints.
4. **Authentication Middleware**:
   - `backend/src/middlewares/auth.middleware.js`:
     - Verifies Clerk Bearer JWT tokens using `@clerk/backend` or Clerk Express SDK.
     - In development or automated test mode (when `CLERK_SECRET_KEY` is a placeholder or `x-user-id` header is passed), populates `req.auth = { userId }` to allow seamless verification via curl/Postman.

  - Direct frontend data hookup (reserved for Phase 4).

---

## 7. Security Considerations
- Authentication required on `GET /api/progress` and `POST /api/progress`.
- Parameter validation and sanitization on all endpoints.
- Database credentials stored exclusively in server environment variables.
- Centralized error handling obscures internal stack traces in production.

---

## 8. Acceptance Criteria
1. Drizzle ORM schema defined in `backend/src/db/schema.js` accurately implements `users`, `courses`, `modules`, `lessons`, and `progress`.
2. Initial migration generated into `backend/src/db/migrations`.
3. Seeding script parses courses and lessons from `docs/seed.ndjson` and `docs/videos.json`.
4. `GET /api/courses` returns HTTP 200 with list of courses.
5. `GET /api/courses/:slug` returns HTTP 200 with course details, modules, and lessons.
6. `GET /api/lessons/:slug` returns HTTP 200 with lesson details, youtube video ID, and notes.
7. `GET /api/progress` returns HTTP 200 with user progress for authenticated user (or 401 without auth).
8. `POST /api/progress` saves/updates progress and returns HTTP 200 with updated state.
9. `npm run lint` passes across all backend files.

## 10. Exact Manual Test Steps
1. Run `npm run db:generate --workspace=backend` to verify migration generation.
2. Run `npm run db:seed --workspace=backend` to verify parsing of `docs/seed.ndjson` and `docs/videos.json`.
3. Start backend server: `npm run dev:backend`.
4. Run `curl http://localhost:5000/api/courses` - verify JSON array of courses.
5. Run `curl http://localhost:5000/api/courses/nextjs-app-router-in-depth` - verify course with modules and lessons.
6. Run `curl http://localhost:5000/api/lessons/nextjs-app-router-in-depth-file-system-routing` - verify lesson video ID `9602Yzvd7ik` and notes.
7. Run `curl http://localhost:5000/api/progress` - verify 401 Unauthorized when missing authentication token or header.
8. Run `curl -H "x-user-id: test-user-1" http://localhost:5000/api/progress` - verify 200 OK with learner progress list.
9. Run `curl -X POST -H "Content-Type: application/json" -H "x-user-id: test-user-1" -d '{"lessonId":"les-1","isCompleted":true,"resumeTimestamp":120}' http://localhost:5000/api/progress` - verify 200 OK with updated progress record.
